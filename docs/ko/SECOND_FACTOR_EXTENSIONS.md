## 구현 상태

네이티브 TOTP 등록과 확인, 시드 암호화, 소유자 인가 및 영속 카운터 제어가
구현되어 있습니다. 6자리, SHA-1, 30초 주기를 사용합니다. 수동 등록은
가능하지만 QR 등록·복구는 미완료입니다. 네이티브 브라우저 TOTP 단계 상승은
소스에 구현되어 있습니다.
등록만으로 세션 인증등급이 올라가지는 않습니다. Google/OIDC 로그인과
인증 앱이 TOTP 코드를 생성하는 기능은 별개입니다.

`src/factor/external.rs`는 신뢰된 챌린지 문맥에 대해 외부 요소 응답을
검증합니다. 파싱 경계이며 활성 커넥터, 서명 검증기, 재사용 방지 저장소가
아닙니다. 이 모듈로 외부 요소 HTTP 라우트나 Lua 런타임이 활성화되지는
않습니다. [인증 게이트웨이](AUTH_GATEWAY.md)의 기존 외부 서비스 API
검증 릴레이는 AAL 0 서비스 신원을 발급하며 사람의 2차 인증 근거가 아닙니다.

네이티브 `external_transport`와 `external_service`가 HTTPS 인증 receipt와 schema v6
소유자의 원자적 완료를 제공합니다. root 설정은 시작 시 verifier를 컴파일·게시합니다. 외부 portal 폼은
구현되었으며 Lua 런타임은 아직 활성화하지 않았습니다. 아래 기록은 단계별 구현 상태이며 최신 소유자 구현 절이
영속 외부 완료가 없다는 과거 문구를 대체합니다.

## 네이티브 권한과 확장 경계

호패가 챌린지 생성, 신원 결합, 자격 세대, 제공자·설정 리비전, 유입 제한,
만료 및 최종 세션 발급을 소유합니다. 커넥터는 설정된 인증 요소 하나를
검증할 수 있으나 사용자, 서비스, 역할, 권한, AAL, 응답 헤더, 리다이렉트
목적지를 선택할 수 없습니다. 서비스 접근 정책은 품계가 소유합니다.
수문장의 네트워크 근거는 인증 조건을 제한할 수 있지만 IP 허용 목록만으로
2차 인증이 되지는 않습니다.

확장 대상은 네이티브 TOTP, 향후 WebAuthn, 외부 검증 API의 푸시·조직 MFA
등 승인된 요소입니다. 등록, 확인, 챌린지, 검증, 철회, 복구 및 서킷 브레이킹을
같은 생명주기로 지원해야 합니다. 이들은 구현 요구사항이며 현재 모든 기능이
제공된다는 의미는 아닙니다.

## 외부 API 계약

설정된 HTTPS 검증기로 서버 소유 챌린지 ID, 불투명 사용자·세션, 정확한
서비스·요소, 설정 리비전·자격 세대와 해당 요소 응답만 전달합니다.
엔드포인트, 신뢰 CA, 인증 비밀 참조, 타임아웃은 관리자 설정입니다.
브라우저가 URL, 발급자, 헤더, 비밀 참조를 선택할 수 없습니다.
리다이렉트와 환경 프록시를 끄고 기존 릴레이의 목적지·DNS 검증을 적용합니다.
검증기·설정 리비전별로 제한된 전용 커넥션 풀과 서킷을 유지합니다.
OTP와 인증 자격은 로그, 트레이스, 감사 속성 및 분석 익스포트에 넣지 않습니다.

응답 필드는 정확히 다음과 같습니다.

```json
{"active":true,"challenge":"c_test","user":"u_test","session":"s_test","service":"orders","factor":"partner-push","configuration_revision":7,"credential_generation":3,"proof_id":"proof_once","expires_at":4000}
```

시간은 Unix 밀리초이며 예시는 실제 요청이 아닙니다. 정확한 문맥 일치,
0보다 큰 설정 리비전, 길이 제한 식별자, 중복·미등록 필드 금지, 최대 8 KiB
본문을 검사합니다. 만료는 수신 이후, 챌린지 수명 이내, 교환 시작부터 최대
5초여야 합니다. 별도의 단조 경과 시간도 통신을 포함해 5초를 넘을 수 없습니다.
시계 역행, 잘못된 응답·문맥, 인증등급 주장은 성공 근거가 아닌 오류·불가용입니다.
문맥이 유효한 `active:false`는 거절입니다. 네트워크 계층은 버퍼링 전에
전체 타임아웃과 본문 제한을 적용해야 합니다. 5초는 근거 수명 한계이지 권장
타임아웃이 아니며 빠른 검증 프로필은 훨씬 짧은 제한을 사용해야 합니다.

비직렬화 `Evidence`의 필드는 비공개이며 세션 권한이 없습니다. 호출자는
검증기 전송 계층을 인증하고 서버의 영속 챌린지 문맥을 사용해야 합니다.
브라우저가 보낸 JSON을 파싱하는 것만으로는 충분하지 않습니다. 최종 커밋은
현재 문맥을 재검사하고 검증 권위·설정 범위의 증명 유일 소비를 보장해야 하며
프로세스 간 재사용도 막아야 합니다. 검증기는 이러한 영속 제어를 구현하지 않습니다.

## 원자적 완료와 장애

하나의 소유자 트랜잭션에서 대기 챌린지와 TOTP 카운터 또는 외부 증명을
소비하고 등록·제공자·설정·사용자 리비전 및 자격 세대를 검사합니다.
인증 근거 추가, 네이티브 정책에 따른 등급 상승, 자격 세대 증가, 이전 핸들과
대기 핸드오프 코드 철회, 교체 포털 핸들과 서비스 결합 핸드오프 생성도
같이 처리합니다. 감사·아웃박스 실패는 모든 변경을 롤백합니다.
이전 핸들은 상승된 등급을 상속하지 않습니다. 기존 포털 브라우저 및 검증된
애플리케이션 복귀 대상 결합은 필수이며 임의 복귀 URL은 거부합니다.
동시 증명·카운터 사용은 하나만 성공해야 합니다.

제공자 호출 전에 프로세스 전체 및 신원·챌린지별 유입 제한을 적용합니다.
타임아웃, 잘못된 응답, 과부하, 열린 서킷에서는 더 약한 제공자로 우회하지
않고 거절합니다. 유효한 자격 거절과 제공자 장애를 구분합니다.
복구는 명시적·감사 가능·속도 제한 대상이며 장애가 인증 우회로 바뀌면 안 됩니다.
OTP 결정은 캐시하지 않습니다. 향후 외부 근거 캐시도 증명·챌린지 수명과
정책 리비전에 묶이고 일회성 소비를 유지해야 합니다.

## Lua 확장 설계

Lua는 허용된 커넥터 호출을 조합하고 타입화된 요소 결과를 반환할 수 있습니다.
DB·세션 쓰기, 환경 변수 조회, 임의 파일·네트워크 접근, 원시 업스트림 자격
이름공간은 제공하지 않습니다. 호스트 함수는 승인된 검증기 참조와 제한된
입력만 제공합니다. 명령 수·메모리·동시성·전체 시간 예산을 적용하며 스크립트
오류, 예산 소진, 취소는 완료를 거절합니다. 스크립트는 `Evidence` 생성,
AAL 설정, 네이티브 커밋 검증 우회를 할 수 없습니다. 검증된 스크립트를
불변 리비전 스냅샷으로 게시하고 진행 중 챌린지를 정책 변경과 결합합니다.
요소 독립성과 허용 인증등급 기여는 네이티브 설정이지 스크립트 주장이 아닙니다.

## 활성화 전 필수 검증

- 실제 브라우저의 보호 서비스 로그인, 단계 상승, 상승 핸드오프 및 모든
  이전 핸들·코드 거절.
- 동시 OTP·증명 사용, 완료 중 등록 철회, 사용자·제공자 비활성화,
  설정 변경 및 감사 롤백.
- 자체 HTTPS 검증기에서 성공·거절, 재사용, 다른 사용자·서비스 챌린지,
  잘못된 본문, 리다이렉트, 타임아웃, 과부하, 서킷 복구, 취소.
- Lua 예산 탈출·금지 호스트 기능 및 게시 경쟁, 복구와 키 유지·교체.
- Hangang 콘솔 탐색과 등록·단계 상승 상태 표시. 콘솔 위임 브로커로 OTP
  시드를 전달하지 않음.

핸들 교체는 [ADR-0008 · 영문](../adr/0008-second-factor-extension-point.md),
기존 릴레이는 [인증 게이트웨이](AUTH_GATEWAY.md)를 참조하십시오.

## 네이티브 TOTP 원자적 완료

네이티브 `elevate_authorized` 서비스는 실제 TOTP 코드를 먼저 소비하지 않고
검증한 뒤 하나의 소유자 트랜잭션을 호출합니다. 만료되지 않은 `stepup`
트랜잭션과 리비전 결합 TOTP 카운터 소비, 인증 근거 추가, 세션·포털 핸들 AAL 2
설정, 자격 세대 증가, 모든 이전 핸들·대기 핸드오프 회수 및 교체 포털 핸들과
정확한 복귀 대상 핸드오프 삽입을 함께 처리합니다. 1차 제공자 인증 시각은
유지합니다. 필수 증명·회수·핸드오프 감사와 아웃박스 쓰기도 같은 트랜잭션입니다.

네이티브 `stepup`에만 `conflicting_handle_sha256`을 시작 포털 핸들 결합으로
사용하며 다른 목적에서는 기존 의미를 유지합니다. 챌린지는 새 핸드오프와
같은 세션·애플리케이션 복귀 대상·브라우저 결합 다이제스트·클라이언트 IP·복구
깊이를 지정해야 합니다. OAuth 제공자·state·nonce·PKCE·재인증 메타데이터는
없어야 합니다. 교체 자격은 기존 핸들·세션 수명 또는 60초 핸드오프 수명을
넘길 수 없습니다. 세션 서비스가 actor를 갱신하며 소유자 쓰기 잠금 안에서
제공자 종류·설정을 재검사합니다. 네이티브 등록과 해제에도 같은 설정 검사를
적용합니다.

실제 TOTP 계산과 SQLite 쓰기 테스트로 원자적 성공 상태, 동시 챌린지의
단일 성공, 잘못된 코드·감사 유일성 실패·다른 챌린지와 세대·복귀 대상·핸들,
제공자 비활성화·변경, 오래된 actor, 만료 챌린지, 철회 등록을 검증합니다.
모든 거절에서 증명·챌린지 및 자격 상태가 보존됩니다. 서비스·저장소 검증이며
실제 브라우저 step-up 검증은 아닙니다.

활성화 전 브라우저 챌린지 생성·CSRF·포털과 애플리케이션 결합, 현재
애플리케이션 정책·설정 epoch 검사, 복구·탐색 및 배포가 필요합니다.
호출자가 두 브라우저 결합과 현재 정책의 복귀 대상을 검증해야 하며 저장소
명령은 애플리케이션 권한을 독립적으로 판단하지 않습니다. 제공자 설정의
구조적 동등성은 단조 게시 epoch나 환경 비밀·CA 내용 지문이 아닙니다.
이 primitive로 런타임 라우트가 활성화되지는 않으며 내부 배포 이미지도 유지합니다.

## 요청 인증등급 집행

세션 검증은 신원 발급 전에 정규화 경로와 일치하는 모든 규칙을 적용합니다.
AAL 2는 세션과 발급 핸들 모두 해당 등급이고 실제 TOTP·WebAuthn·복구 요소
기록이 있어야 합니다. `max_age`는 1차 인증 시각이 아닌 최신 요소 확인 시각을
검사합니다. 없는 근거, 만료·미래 시각, 이전 등급 1 핸들은 통과하지 않습니다.
AAL 1 신선도 규칙은 1차 인증 시각을 사용합니다. 비일치 경로는 일반 인증
동작을 유지하며 규칙이 하나라도 설정되면 캐시를 막습니다.

브라우저 챌린지 생성·완료가 미구현인 동안 미충족 규칙은 문서 403 또는
API·세션 401 `step_up_required`로 처리합니다. 미지원 리다이렉트, 핸들 삭제,
불완전 챌린지는 발급하지 않습니다. 완전한 MFA를 주장하기 전 이 거절을
브라우저 결합 step-up 흐름으로 연결해야 합니다.

서비스 API 자격은 AAL 0을 유지합니다. 인증 후 공유 HTTP·HOP1 경로에서
현재 애플리케이션 스냅샷을 검사하여 사람 인증등급 규칙이 일치하거나
애플리케이션이 비활성화·미등록이면 서비스 신원 헤더 없이 거절합니다.
유효한 API 키라도 사람 인증등급 규칙을 우회하거나 거절 후 사람 세션으로
우회할 수 없습니다. 품계는 서비스 권한을 별도로 집행합니다.
정규화·대문자 접두사, 없는 근거·등급 숫자만 있는 근거·OIDC만 있는 근거,
오래된·미래 OTP, 이전 발급 핸들, 오래된 1차 인증과 새 OTP, 비일치 경로,
스냅샷 변경 후 HTTP·네이티브 서비스 거절을 테스트합니다.

네이티브 관리자 리스너는 인증등급 거절을 로그인 부재로 잘못 분류하지 않고
기존 `aal_insufficient` 응답·지표·필수 감사 이벤트에 연결합니다. 접두사 매칭은
요청마다 소문자 문자열을 할당하지 않고 ASCII 바이트를 비교하며 기존 UTF-8·
경로 세그먼트 의미를 유지합니다. 전체 스택 처리량 검증은 아닙니다.

## 영속 포털 챌린지 결합

네이티브 `bind_stepup` 서비스가 트랜잭션·포털 쿠키 형식을 검사하고 최근
네이티브 요소 actor로 하나의 소유자 쓰기를 인가합니다. 소유자가 사용자의
활성 TOTP 등록을 선택하고 만료되지 않은 `stepup` 트랜잭션을 같은 유효한
세션·정확한 포털 핸들·포털 쿠키 다이제스트·클라이언트 IP·자격 세대·등록 ID·
등록 리비전에 결합합니다. 애플리케이션 결합은 이미 있어야 하며 OAuth·재인증
필드는 없어야 합니다. 문맥에 시드·쿠키·Bearer 원문을 저장하지 않습니다.

`stepup`에만 `pending_identity`를 네이티브 세대·등록 문맥으로 사용하며
다른 트랜잭션 목적의 기존 의미는 유지합니다. 같은 유효한 결합의 재준비는
성공하고 감사 이벤트를 추가하지 않습니다. 다른 브라우저 쿠키·핸들·IP,
변경된 자격 세대·활성 등록 리비전은 이를 교체할 수 없습니다. 결합과 필수
감사·아웃박스 삽입은 함께 커밋합니다. 최종 OTP 승격 트랜잭션이 포털 쿠키
다이제스트와 정확한 기록 문맥을 비교한 뒤 챌린지·카운터를 소비하며 새
핸드오프 IP도 네이티브 actor의 현재 요청 IP와 같아야 합니다. 거절은 정상
브라우저의 두 증명을 정상 만료 전까지 소비하지 않습니다.

소유한 SQLite·서비스 테스트로 최초 결합·멱등 새로고침, 쿠키·핸들 이전,
IP 변경, 세대 변경 후 갱신한 actor, 등록 리비전 변경, 다른 목적, 만료,
애플리케이션 결합 없음, 소비된 챌린지, 잘못된 쿠키, 감사 롤백·성공 재시도를
검증합니다. 최종 완료에서도 잘못된 쿠키·문맥·IP를 등급 상승이나 카운터·
챌린지 소비 없이 거절합니다. 실제 브라우저 step-up 검증은 아닙니다.
요청 엔진은 미충족 규칙을 계속 거절하며 브라우저 챌린지 생성·포털 페이지·
CSRF·검증된 복귀 대상과 정책 epoch 검사·운영 활성화가 필수 후속입니다.

## 네이티브 브라우저 OTP 흐름

TOTP keyring이 설정되면 `GET /stepup?txn=...`과 `POST /stepup`을 활성화합니다.
AAL 2 규칙이 미충족인 문서 요청은 기존 핸들을 유지하며 유입 제한된 같은
세션의 챌린지를 시작합니다. API 요청은 챌린지 없이 401입니다. Keyring이
없으면 AAL 2 문서는 거절합니다. AAL 1의 1차 인증 신선도 요구는 OTP 반복
대신 제공자 재인증으로 처리합니다. 1차 인증이 5분보다 오래되면 네이티브
AAL 2 시작도 2차 인증 완료 전에 재인증합니다.

포털은 HTTPS·유효한 본인 핸들을 요구하고 현재 앱 설정으로 복귀 대상을
검증하며 소유자 저장소에서 챌린지를 결합합니다. 미등록 사용자는 코드 폼
대신 등록·계속 링크를 받으며 등록만으로 등급이 상승하지 않습니다.
완료 폼은 트랜잭션·포털 쿠키·핸들에 묶인 별도 CSRF 목적, 정확한 Origin,
유일 필드, 6자리 코드, 본문 제한 및 기존 IP별 시도 제한을 적용합니다.
임시 결합 Bearer 문자열은 zeroize합니다. 일반 로그인·제공자 진입점은
step-up 트랜잭션을 거절하여 새로고침이 약한 흐름으로 우회하지 못합니다.

네이티브 포털 준비·완료에 현재 설정 세대를 전달합니다. 소유자 트랜잭션이
쓰기 잠금 안에서 영속 `meta.config_generation`과 비교하고 챌린지 문맥에
기록합니다. 게시·재시작 설정 변경은 챌린지·카운터 소비 전에 완료를
무효화합니다. 일반 신뢰 서비스·저장소 primitive는 내부 호출·테스트를 위한
선택적 비검사 세대를 유지하지만 HTTP 포털은 항상 세대를 제공합니다.
완료 전 복귀 대상을 재검증합니다. 네이티브 인증등급 발급은 인증 근거이며
서비스 권한은 품계가 소유합니다.

유효한 새 OTP는 증명·챌린지 소비, 등급 상승·자격 교체, 정확한 복귀 대상
핸드오프 발급을 원자적으로 처리합니다. 포털이 교체 쿠키를 설치하고 기존
애플리케이션 호스트의 핸드오프 소비를 통해 이동합니다. 저장소 장애·손상은
자격 거절 대신 불가용으로 처리합니다. 시드·코드는 이동 URL·감사 payload에
넣지 않으며 no-store·CSP를 유지합니다.

자체 OIDC·실제 프로세스 HTTP fixture로 미등록 안내, 암호화 등록·비승격
확인, 문서 단계 상승·실제 OTP, Origin·다른 목적·익명·중복 쿼리 거절,
일반 로그인 경로 오용 거절, 새 핸드오프 소비·AAL 2 보호 접근, 이전 핸들
거절·완료 재사용 거절을 검증합니다. 테스트 브라우저 클라이언트·쿠키 jar이며
Chromium·모바일 앱 검증은 아닙니다. 소유자 테스트는 설정 변경·다른 세대·
0 세대에서 증명 미소비를 확인합니다. 복구·취소·해제 UI, QR·모바일 검증,
계정·분산 시도 제한, 키 수명주기, Hangang 메뉴 및 내부 MFA 배포는 남습니다.
이전 브라우저 연결 미구현 기록은 과거 소스 단계이며 내부 배포
`owner-v5-d876909`는 유지합니다.

## 브라우저 이동 CSP 검증

실제 Chromium 후보 테스트에서 소유자 트랜잭션이 성공해도
`form-action 'self'`가 OTP POST 후 다른 origin의 핸드오프를 막는 것을
발견했습니다. 단계 상승 서비스가 현재 설정으로 검증한 복귀 대상 origin만
반환하고, 기존 페이지별 CSP helper가 GET 폼에 정확히 그 origin을 추가합니다.
와일드카드·요청 입력 목적지는 허용하지 않습니다. HTTP fixture가 정확한
origin 허용을 검사합니다. `tools/qualify_browser_totp.py`는 비공개 소유자 상태
복사본·자체 1차 인증 세션 fixture를 가진 독립 loopback 후보에서 실제
브라우저의 폼 Origin·쿠키 교체·CSP 이동·핸드오프를 검증합니다. 실제 Google
사용자 인증이나 TLS ingress 검증은 아니며 CDP가 HTTPS 브라우저 origin을
후보 HTTP 리스너로 전달합니다. 네이티브 mTLS는 별도로 검증합니다.

## 내부 런타임과 Chromium 증거

수정한 정적 후보가 실제 Chromium 등록·브라우저 단계 상승과 이동·핸드오프·

배포 후 실제 서비스 매트릭스 권한·거절·자격 제거, 모듈 메뉴·독립 품계
매트릭스, SSO 진입·로그아웃·origin 격리·네이티브 전송 회귀가 통과했습니다.
일관된 소유자·위임 DB와 기존 이미지·설정·비밀 파일을 비공개 롤백 자료로
보관합니다. 이전 배포 이미지 기록은 과거 런타임 단계입니다. 운영 사용자
MFA·복구·계정 및 분산 시도 제한·키 폐기와 재암호화·메뉴·전체 스택 성능은
여전히 미검증·미완료이며 선택적 런타임 활성화로 전체 인증 게이트웨이나
제로트러스트 백본의 완료를 주장해서는 안 됩니다.

## 외부 HTTPS 호출 프리미티브 — 2026-10-14

`src/factor/external_transport.rs`가 고정된 인증 HTTPS factor 요청을 호출하고 기존
문맥 파서로 응답을 검증합니다. 네이티브 라이브러리 프리미티브이며 활성화된 portal·
provider 설정은 아닙니다. 운영 사용자 인증 전에 영속 증명 소비, 소유자 등급 상승,
런타임 게시와 Lua 호출 연결이 필요합니다.

타입 설정은 factor, 0이 아닌 configuration_revision, 고정 HTTPS url,
verifier_key_env, timeout_ms(1–1000), allow_private_endpoints와 선택적인 절대 CA
경로입니다. private endpoint를 허용해도 HTTP는 거부하며 CA·서버 이름 검증을 유지합니다.
환경 프록시와 redirect를 끄고 public 목적지에는 검증한 DNS·주소 선택을 적용합니다.
해석된 verifier key와 custom CA 파일 내용도 불변 binding에 포함하여 같은 참조의
실제 값이 바뀌면 기존 connector를 재사용할 수 없습니다.

connector마다 대기 없이 최대 64개 동시 호출을 허용합니다. idle pool은 origin별
최대 64개 연결을 30초 유지합니다. 전체 기한은 TLS·요청·응답 본문을 포함하며 선언된
길이와 streaming 본문 모두 8 KiB 초과 시 전체 버퍼링 전에 거부합니다. 인증 응답 입력은
4096바이트 이하입니다. 재시도·캐시·더 약한 provider fallback은 없습니다. 서버 소유
`started_at`는 브라우저 challenge 생성 시간이 아닌 이번 검증 교환의 준비 시점입니다.
5초 근거 수명은 그 시점부터 계산하고 challenge의 별도 만료도 적용합니다. 교환 중
관찰된 벽시계 역행은 완료를 거부합니다.

HTTP 200의 정확한 문맥에 결합된 타입 JSON 응답만 유효한 factor 판정입니다.
유효한 `active:false`는 정상적인 자격 거부입니다. 단순 401·403, redirect, 문맥 불일치,
임의 등급 주장, 잘못된 응답, timeout과 취소는 verifier 실패로 처리하며 3회 실패하면
30초 서킷을 엽니다. 비밀·응답 본문·proof·URL을 포함하는 전송 오류는 출력하지 않습니다.

자체 TLS 테스트가 OpenSSL로 격리된 CA·서버 인증서를 생성합니다. 성공·거절 근거,
실제 연결 재사용, 잘못된 CA, 사용자 교차·등급 주입, 잘못된 본문·type·status,
서버가 stream을 유지하는 header·chunked 크기 상한, 본문·교환 기한, 동시성 거부,
취소, 서킷 거부·복구, 시계 역행과 비밀·CA 값 변경 binding을 검증합니다. 이 결과는
브라우저 외부 MFA, 영속 재사용 방지나 분산 세션 등급 상승의 검증은 아닙니다.

## 네이티브 외부 증명 소비와 등급 상승 — 2026-10-14

HTTPS connector는 정확한 검증 문맥과 불변 authority를 가진 비공개·직렬화 불가·
복제 불가 `VerifiedProof`를 반환합니다. 원본 proof ID는 전송 계층에서 나가기 전에
해시합니다. 일반 JSON 파서 결과를 소유자 완료에 전달할 수 없습니다. receipt는
벽시계 만료와 교환의 5초 예산에 제한된 단조 기한을 함께 가집니다. 벽시계가 멈춰도
소유자 대기·쓰기 시간이 증명의 수명을 늘리지 않습니다.

`external_service::elevate_authorized`가 대기 중인 네이티브 transaction을 현재 actor,
portal cookie 해시, 최초 portal handle, 자격 세대, factor·revision·binding과 현재
설정 epoch에 결합한 뒤 고정 verifier를 호출합니다. 사용자·session·서비스는 소유자에서
도출하며 브라우저 transaction bearer token 대신 transaction 해시를 전달합니다.
교환 후 소유자 쓰기 transaction에서 다시 검사하여 비활성·변경 authority, 1차 provider·
사용자 변경, 오래된 actor·handle·generation, 다른 서비스·target·브라우저 binding,
만료 증명을 거부합니다. commit 직전에도 만료와 시계 역행을 검사합니다.

schema v6은 승인된 외부 factor authority, factor별 session 인덱스, 영속 proof 해시
원장과 용량 counter·trigger를 추가합니다. factor authority와 설정 revision 내 proof
고유성을 사용자·session·challenge를 넘어 적용합니다. 한 소유자 transaction에서 proof와
challenge 소비, 네이티브 `external` factor 추가, AAL 2와 자격 세대 증가, 이전 모든
handle·미사용 code 회수, 새 portal handle·정확한 target의 elevated handoff 발급,
필수 `factor.external_consumed`·회수·handoff 감사와 outbox를 처리합니다. 감사나 용량
실패는 완료 전체를 롤백합니다. 1차 인증 시간은 유지합니다. 네이티브 운영자가 승인한
독립적인 2차 verifier만 게시할 수 있으며 AAL 0 서비스 API relay는 해당 authority가 아닙니다.

disable tombstone을 포함하여 factor 식별자는 최대 64개 유지합니다. revision과 이전에 게시한 전역 epoch는 낮출
수 없고 해석된 비밀·CA·verifier 설정이 바뀌면 같은 revision을 재사용할 수 없습니다.
동일 authority는 proof 이력을 지우지 않고 새 전역 설정 epoch를 따를 수 있습니다.
revision·실제 값 변경이나 disable은 해당 factor로 등급이 올라간 session을 종료하고
handle·code를 원자적으로 회수합니다. 모든 session JSON을 스캔하지 않고 factor/session
인덱스를 사용합니다. 기존 네이티브 TOTP 등록 제거는 최근의 네이티브 외부 MFA도 인정합니다.

소유자 재개방과 일반 session 정리 이후에도 소비된 해시를 유지하며 자동 proof 삭제는
없습니다. 원장 상한은 1,000,000행이고, 가득 차면 재사용 이력을 버리지 않고 새 완료를
거부합니다. 안전한 보관·퇴역과 운영 용량 telemetry는 후속 lifecycle 작업입니다.
시작 precheck는 정확한 v6 제약·guard와 counter 일관성을 읽기 전용으로 검증합니다.
v5 바이너리는 v6 상태를 열 수 없으며 rollback에는 일관된 이전 owner·delegation 백업과
설정·키가 필요합니다. 내부 런타임은 schema v5를 유지하며 이번 소스로 마이그레이션하지 않았습니다.

자체 TLS와 소유자를 연결한 테스트가 elevated handoff, 이전 자격 회수, 동시·session간
proof 재사용, 재개방 후 영속성, factor disable, 문맥·세대·브라우저·앱 오류,
provider·사용자·authority·설정 변경, 벽시계·단조 만료, 용량·감사 롤백을 검증합니다.
foundation 테스트는 구조·guard 누락과 counter 손상을 거부합니다. 네이티브 서비스와
SQLite 소유자 검증이며 실제 브라우저 외부 MFA나 독립 follower DB 간 재사용 방지 검증은
아닙니다. root snapshot 게시, 서비스별 factor 선택·등록, 브라우저 UI·CSRF·유입 제한,
프로세스 전체 유입 제한, Lua 연결과 fleet 검증은 남아 있습니다.

네이티브 external_registry는 최대 64개의 고유한 factor 설정을 모두 검증·컴파일한
후 새 snapshot을 반환합니다. 비밀 누락이나 CA·클라이언트 설정 오류는 후보 전체를

않습니다. 운영 활성화 전에 원자적 소유자 정합 처리와 root·portal 연결이 필요합니다.

## 전체 verifier 원자적 게시

registry가 운영자가 승인한 원하는 전체 구성을 한 소유자 transaction으로 게시합니다.
영속 snapshot revision을 compare-and-swap에 사용하며 단일 factor 변경도 이를
증가시켜 오래된 전체 게시가 중간 disable·회전을 덮어쓰지 못하게 합니다. 전역 설정
 epoch 검사는 게시 revision과 별도로 적용합니다. 소유자 게시 성공 후에만 메모리
registry를 활성화해야 합니다.

이전 활성 authority가 새 구성에 없으면 revision을 증가시킨 disable tombstone으로
바꾸고 기존 factor/session 인덱스로 관련 elevated session·handle·code를 회수합니다.
이미 비활성인 항목은 반복 누락 시 revision을 유지합니다. tombstone과 proof 이력을
유지하여 재사용과 낮은 revision의 재활성화를 막습니다. 추가·제거·세션 회수·게시
revision·필수 감사·outbox가 함께 commit되며 뒤늦은 충돌·용량·고갈·감사 실패는 전체를
롤백합니다.

자체 TLS·소유자 테스트로 동시 제거, 기존 proof 유지, 단일 변경 후 오래된 전체 게시
거부, 잘못된 전역 epoch, 뒤늦은 factor 충돌과 이전 elevated session이 있는 상태의
최종 감사 실패 롤백을 검증합니다. 네이티브 게시 프리미티브이며 root 설정·브라우저
factor 선택·Lua는 활성화하지 않습니다. 분산 follower 전파 검증은 아닙니다.

## 시작 시 registry 활성화 — 2026-10-14

타입화된 root 설정 `external_verifiers`가 서버 시작의 컴파일·원자적 소유자 게시 경로에
연결되었습니다. 값 누락은 상태 디렉터리 생성 전에 거부합니다. 게시 성공 후 Services를
활성화하고 리스너를 바인딩합니다. 빈 원하는 구성은 재시작 시 기존 authority를 정합 처리합니다.
`factor.registry_published`는 snapshot과 함께 commit하는 필수 이벤트이며 전체 앱의
`config.loaded`와 별개입니다. 등록 이벤트 33개 중 필수 28개, 진단 5개입니다.

실제 프로세스 테스트로 자체 verifier 참조를 설정해 호패를 시작하고, 원격 호출 없이
게시된 authority·revision을 확인한 뒤 설정 제거·재시작의 disable tombstone을 검증합니다.
단위 테스트는 상태 생성 전 비밀 누락, 중복 참조, caller 인증과 비밀을 출력하지 않는
검증을 다룹니다. 과거 root 연결 부재 기록을 대체하며 외부 브라우저 실행, factor 등록·
선택, Lua와 fleet 운영은 후속입니다. 내부 배포는 기존 schema v5 이미지를 유지합니다.

개별 authority 게시의 필수 이벤트는 `factor.authority_published`, 전체 registry는
`factor.registry_published`입니다. 둘 다 소유자 상태와 함께 commit하며 독립 이벤트
append로 삽입할 수 없습니다.

## 네이티브 외부 브라우저 응답 경로 — 2026-10-14

설정된 외부 registry가 TOTP와 함께 문서 step-up을 활성화합니다. `/stepup?txn=...`는
HTTPS의 현재 portal session·transaction을 검증한 뒤 승인된 factor와 선택적인 TOTP를
표시합니다. 외부 선택은 `/stepup/external?txn=...&factor=...`에서 소유자 challenge에
해당 factor를 결합합니다. 이미 결합한 challenge를 다른 factor로 전환할 수 없으며
TOTP도 명시적으로 선택합니다. 외부 실패 후 더 약한 provider로 자동 fallback하지 않습니다.

외부 POST는 transaction·factor·CSRF·response 네 필드만 허용합니다. 별도 CSRF purpose를
transaction·portal cookie·handle·factor에 바인딩하고 기존 비밀번호·TOTP의 정확한 Origin,
HTTPS, 본문 상한과 프로세스 공유 IP 제한을 적용합니다. response는 비어 있지 않은
4096바이트 이하이며 브라우저가 URL·신원·role·AAL을 선택할 수 없습니다. 폼 CSP는 현재
검증된 앱 Origin만 handoff에 허용하며 response·verifier 자격은 출력·로그에 넣지 않습니다.

adapter가 소유자 문맥으로 먼저 검증하고 TOTP·외부 공통 발급 helper로 새 자격을 생성한 뒤
불투명 receipt를 원자적으로 commit합니다. 생성 시각은 미래이거나 5초보다 오래될 수 없고
handle 활동·handoff 생성 시각도 일치해야 합니다. 비동기 검증의 초 경계로 인한 불필요한
실패를 피하면서 actor·proof 벽시계·단조·commit 직전 검사도 유지합니다. verifier 요청에
서버 소유 밀리초 `verification_started_at`를 challenge 만료와 함께 전달하여 짧은 proof
수명을 구현할 수 있게 합니다. 엄격한 응답 schema는 유지합니다.

자체 OIDC·HTTPS 실제 런타임 테스트는 1차 로그인, chooser, 외부 폼, backend 호출 전
Origin·CSRF·추가 필드 거부, 문맥에 맞는 거절, 사용자 교차·등급 주입 거부, AAL 2
handoff·보호 요청과 이전 handle 거부를 검증합니다. 시간 테스트는 초 경계와 오래된·미래
자격 거부를 다룹니다. 실제 cookie·프로세스 경계의 HTTP 브라우저 클라이언트이며 Chromium이나
운영 조직 MFA 계정 검증은 아닙니다. 실제 브라우저·fleet·성능·운영, 서비스별 factor 자격,
등록·복구·계정 유입 제한·Lua는 후속입니다. 내부 v5 이미지는 유지합니다.
