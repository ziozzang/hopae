# 문서 체계

<!-- translation-status: source=../DOCUMENTATION.md source-rev=1 status=current -->

[문서 목차](README.md) · [English](../DOCUMENTATION.md)

이 문서는 Hopae 문서가 어디에 있는지, 두 언어를 어떻게 맞추는지, 페이지를 어떻게
쓰는지, 그리고 모든 기능이 어떤 문서와 함께 출시되어야 하는지를 정의합니다.
[개발 프로세스](PROCESS.md)는 문서 게이트에서 이 규칙을 참조합니다.

## 구성

```text
README.md                     제품 개요와 진입점(영문, 기준)
README.ko.md                  README.md의 한국어 번역
CHANGELOG.md                  Keep a Changelog, 영문 전용
LICENSE                       MIT
release-public-key.txt        서명된 릴리스의 Ed25519 검증 키(M6부터)
docs/
  README.md                   영문 문서 목차
  PROCESS.md                  개발 프로세스
  DOCUMENTATION.md            이 문서
  ROADMAP.md                  마일스톤과 시나리오 번호 범위
  THREAT_MODEL.md             살아 있는 위협 모델(M0부터)
  <TOPIC>.md                  기능별 참조 페이지 하나, 영문 기준
  ko/
    README.md                 한국어 문서 목차
    <TOPIC>.md                원문과 같은 파일 이름의 한국어 완역
  adr/
    0000-template.md          ADR 템플릿
    NNNN-kebab-title.md       결정마다 기록 하나, 번호는 재부여하지 않음
scenarios/
  README.md                   번호 범위와 상태 범례
  000-template.md             시나리오 템플릿
  NNN-kebab-name.md           시나리오마다 실행 가능한 명세 하나
deploy/                       이식 가능한 배포 템플릿, 운영자 사본은 로컬에 둠
internal/                     비공개(gitignore): 역할과 도구, 검토 보고서,
                              배포 영수증, 공개 거부 목록
```

구성 규칙:

- 영문 참조 페이지는 `docs/` 바로 아래에 둡니다. 한국어 번역은 `docs/ko/`에 **같은 파일 이름**으로 둡니다. 그 밖의 중첩은 없습니다.
- 파일 이름은 안정적인 식별자입니다. 페이지 이름을 바꿀 때는 이전 이름에 리디렉션 스텁을 마이너 버전 하나 동안 남깁니다.
- `internal/`과 `TODO.md`는 `.gitignore`로 제외합니다. 공개 파일은 `internal/`로 링크하지 않습니다. 공개 페이지는 "내부에 기록함"이라고만 말할 수 있습니다.
- `docs/adr/`과 `scenarios/`는 의도적으로 영문 전용입니다([언어 규칙](#언어-규칙) 참고).

## 언어 규칙

영어가 원본입니다. 한국어 페이지는 요약이 아니라 영문 원문의 **완역**입니다. 모든
절, 표, 예제, 전제 조건, 실패 사례, 제한 사항을 보존합니다. 완전하게 유지할 수
없는 번역은 부분적으로 남기지 않고 삭제한 뒤 영문 페이지 링크로 대체합니다.

### 같은 변경 규칙

영문 페이지와 그 기존 한국어 번역은 같은 커밋이나 같은 검토된 시리즈에서
갱신합니다. 번역이 뒤처진 변경은 검토 대상이 될 수 없습니다.

### 번역 상태 헤더

`docs/` 아래의 모든 영문 페이지와 루트 `README.md`는 H1 바로 다음에 문서 리비전
표식을 둡니다:

```markdown
# Page title

<!-- doc-rev: 3 -->
```

모든 한국어 번역은 같은 위치에 상태 헤더를 둡니다:

```markdown
# 페이지 제목

<!-- translation-status: source=../PAGE.md source-rev=3 status=current -->
```

- `doc-rev`는 양의 정수입니다. 의미가 바뀌는 변경(동작, 기본값, 제한, 명령, 예제, 구조)마다 올립니다. 오타와 서식 수정은 올리지 않습니다.
- `source-rev`는 원문의 `doc-rev`와 같아야 합니다. `status=current`인데 둘이 다르면 `make check-docs`가 실패합니다.
- `status=stale`은 같은 변경에서 번역을 끝낼 수 없었던 `sec/` 핫픽스에만 허용됩니다. 두 파일 중 하나에 대한 다음 변경에서 반드시 해소해야 합니다. `make check-docs`는 `stale`에 경고하고, stale 번역의 원문이 다시 올라가면 실패합니다.
- `source`는 번역 파일에서 원문까지의 상대 경로입니다.

### 예외

다음은 영문 전용이며, 끝에 한국어 요약을 위한 짧은 `## 한국어 요약` 절을 선택적으로
둘 수 있습니다. 이들은 개발자용 역사 기록이거나 실행 가능한 명세로서, 가치가
산문이 아니라 식별자와 정밀성에 있기 때문에 예외입니다.

- `docs/adr/*.md` — 결정은 수락되면 불변입니다. 번역하면 권위를 유지할 수 없는 두 번째 기록이 생깁니다.
- `scenarios/*.md` — 테스트 이름, 헤더 이름, 상태 코드가 대부분이고 Given/When/Then 산문은 짧습니다.
- `CHANGELOG.md` — 릴리스 노트는 영문입니다. 한국어 릴리스 노트를 쓸 때는 GitHub 릴리스 설명에 둡니다.

언어 전환 링크, `GLOSSARY.md`의 이중 언어 용어표, 그리고 펜스 블록이나 인라인
코드 스팬 안에 인용된 형식만이 영문 파일에 한국어가 나타나는 그 밖의 유일한
자리입니다. `make check-docs`는 `docs/*.md`의 다른 곳에 있는 한국어 산문을
거부합니다.

## 문서 종류

| 종류 | 위치 | 목적 | 수명 주기 |
| --- | --- | --- | --- |
| 참조 페이지 | `docs/<TOPIC>.md`(+ `ko/`) | 기능 하나의 현재 동작 기술: 설정, 동작, 실패 양상, 관리 표면, 제한, 검증 | 기능이 바뀔 때마다 갱신. 계획이 아니라 현재 상태만 기술 |
| 설정 참조 | `docs/CONFIG.md`(+ `ko/`) | 모든 설정 키, 타입, 기본값, 제약, 다시 로드 동작 | 키와 같은 변경에서 갱신 |
| 게이트웨이 계약 | `docs/GATEWAY_CONTRACT.md`(+ `ko/`) | 게이트웨이의 인증 확인과 Hopae 사이의 정확한 요청/응답 계약: 엔드포인트, 헤더, 상태 코드, 쿠키, 타임아웃 | 제품과 함께 버전 관리. 1.0 이전의 호환성 깨는 변경은 `Changed` 항목과 마이그레이션 메모가 있을 때만 |
| 위협 모델 | `docs/THREAT_MODEL.md`(+ `ko/`) | 자산, 신뢰 경계, 진입점, 공격자 능력, 위협과 의존하는 완화책, 시나리오 참조 | 모든 보안 관련 변경에서 변경분 추가 |
| ADR | `docs/adr/NNNN-*.md` | 맥락, 대안, 결과, 적대적 검토가 담긴 아키텍처 결정 하나 | Proposed → Accepted → Superseded/Deprecated. 수락 후에는 상태와 링크 외에 수정하지 않음 |
| 시나리오 | `scenarios/NNN-*.md` | 실행 가능한 명세: Given/When/Then, 남용 케이스, 테스트 대응, 실환경 검증 | draft → approved → implemented → verified-live |
| 로드맵 | `docs/ROADMAP.md`(+ `ko/`) | 마일스톤, 범위, 종료 기준, 시나리오 번호 범위 | 마일스톤이 바뀔 때 갱신. 완료 항목은 CHANGELOG로 이동 |
| 프로세스 | `docs/PROCESS.md`, 이 페이지 | 일하는 방법 | ADR을 통해서만 변경 |
| 내부 기록 | `internal/**` | 역할/도구 배정, 검토 맥락 파일과 보고서, 배포 영수증, 환경 특정 정보, 공개 거부 목록 | 절대 공개하지 않음 |

## 문체 지침

모든 페이지의 체크리스트:

- [ ] 문장형 대소문자의 서술적 H1 하나. 다른 H1은 없음.
- [ ] 리비전 또는 상태 헤더 바로 다음에 내비게이션 줄: 영문 참조 페이지는 `[Documentation](README.md) · [한국어](ko/PAGE.md)`, 한국어 참조 페이지는 `[문서 목차](README.md) · [English](../PAGE.md)`. 목차 페이지와 루트 README들은 서로 링크하며, ADR과 시나리오는 대신 각자의 템플릿을 따름.
- [ ] 첫 문단은 기능과 범위를 평이한 말로 밝힘.
- [ ] 참조 페이지는 다음 절 순서를 따르되, 빈 절을 채우기보다 생략:
  1. 전제 조건과 설정
  2. 동작(다시 로드, 실패, 타임아웃 동작 포함)
  3. 관리 API, 콘솔, 관측 가능성
  4. 제한과 호환성
  5. 예제, 검증, 관련 페이지
- [ ] 주요 절은 H2, H3는 H2 안에서만, 단계 건너뛰기 없음.
- [ ] 비교 가능한 옵션은 표로. 명령, JSON, YAML, HTTP, 코드는 언어 태그가 있는 펜스 블록으로.
- [ ] 명령은 따로 밝히지 않는 한 저장소 루트에서 실행. 설정 조각은 조각임을 표시.
- [ ] 현재 동작을 기술. 제한은 현재의 경계로 서술("세션은 인스턴스 로컬이다")하고 과제("TODO: 세션 공유")로 서술하지 않음.
- [ ] 운영자가 얻는 것을 말하고 계약을 소유한 페이지로 링크. 같은 계약을 여러 페이지에 반복하지 않음.
- [ ] 식별자는 언어가 달라도 바뀌지 않음: 설정 키, 헤더 이름, API 경로, 플래그, 지표 이름, 오류 코드, 시나리오와 ADR ID.
- [ ] 예제는 루프백 주소와 예약된 이름(`*.example.test`)을 사용. 운영 호스트, 내부 도메인, IP, 배포 경로, 계정은 절대 금지.
- [ ] 비밀 정보 금지. 실제 형식과 일치하는 가짜처럼 보이는 값도 금지. `<redacted>` 자리 표시자를 사용.
- [ ] 한국어 산문은 정중하고 직접적인 합니다체를 쓰고, `GLOSSARY.md`의 일관된 용어를 사용하며, 자연스러운 범위에서 원문의 문장 경계를 유지. 제목은 번역하고 코드, 키, 값은 그대로 두며 `ko/` 디렉터리에 맞게 상대 링크를 고침.
- [ ] 다른 제품에 대한 주장은 범위를 밝히고 공식 출처로 링크하며 검토 날짜를 기록.

## 기능별 필수 문서

기능(로드맵 항목, 새 제공자, 새 정책, 새 엔드포인트)은 해당하는 모든 행이
없으면 병합할 수 없습니다. "해당" 여부는 G1에서 결정하고 작업 지시서에 기록합니다.

| 문서 | 필요한 경우 | 위치 |
| --- | --- | --- |
| 참조 페이지(영문 + 한국어) | 운영자나 사용자에게 보이는 모든 동작 | `docs/<TOPIC>.md`, `docs/ko/<TOPIC>.md` |
| 설정 참조 항목(영문 + 한국어) | 새로 추가되거나 바뀐 설정 키, 환경 변수, 플래그 | `docs/CONFIG.md`, `docs/ko/CONFIG.md` |
| 게이트웨이 계약 갱신(영문 + 한국어) | 게이트웨이가 보는 헤더, 상태 코드, 쿠키, 엔드포인트의 변경 | `docs/GATEWAY_CONTRACT.md`, `docs/ko/GATEWAY_CONTRACT.md` |
| 위협 모델 변경분(영문 + 한국어) | [보안 규칙](PROCESS.md#보안-규칙)에서 정의한 보안 관련 변경 | `docs/THREAT_MODEL.md`, `docs/ko/THREAT_MODEL.md` |
| 시나리오 | 항상 | `scenarios/NNN-*.md` |
| ADR | 인터페이스, 신뢰 경계, 데이터 모델, 보장을 바꾸는 결정 | `docs/adr/NNNN-*.md` |
| CHANGELOG 항목 | 사용자에게 보이는 모든 변경 | `CHANGELOG.md`의 `Unreleased` 아래 |
| 로드맵 갱신 | 마일스톤의 범위나 순서 변경 | `docs/ROADMAP.md`, `docs/ko/ROADMAP.md` |
| 배포 템플릿 갱신 | 새 런타임 의존성, 포트, 볼륨, 환경 변수 | `deploy/` |

## 검증

의도한 변경을 스테이징한 뒤 실행합니다:

```sh
make check-docs
git diff --cached --check
```

`make check-docs`는 Git 인덱스를 읽으므로 무시된 로컬 파일이 깨진 공개 링크를
감출 수 없습니다. 검사 항목은 다음과 같습니다.

- 로컬 링크 대상이 존재한다(저장소 안의 앵커 포함).
- 모든 참조 페이지(`docs/*.md`, `docs/ko/*.md`)에 H1이 하나이고, 제목 단계 건너뛰기가 없으며, 목차로 가는 내비게이션 줄이 있다. ADR과 시나리오는 H1 하나와 제목 순서만 검사한다.
- 한국어 산문은 `docs/ko/`, 루트 `README.ko.md`, 용어표, 언어 전환 라벨, ADR과 시나리오의 `## 한국어 요약` 절에만 나타난다.
- 위에서 설명한 `doc-rev` / `source-rev` 일치와 `status` 규칙.
- 번역과 원문의 구조 동일성: 같은 순서의 같은 제목 단계, 같은 언어 태그를 가진 같은 개수의 펜스 블록, 같은 표 행 수.
- 공개 정책: `internal/` 아래 파일 없음, 비밀 정보 형태의 문자열 없음, 공개 거부 목록(`HOPAE_PUBLISH_DENYLIST`가 가리키는 저장소 밖 파일에서 읽으며, 사전 커밋 훅이 있으면 자동으로 전달)의 항목 없음.

구조 동일성은 충실한 번역을 증명하지 않습니다. 예제, 기본값, 실패 동작이 바뀔
때마다 검토자가 두 언어를 모두 읽습니다. 검사기는 외부 URL을 검증하거나 서버에
대해 명령을 실행하지 않습니다.
